# Quest Game: context for Claude

An engine for secret-quest party games among friends: a mobile-first PWA (Vite + React + TypeScript) on Firebase (Auth, Firestore, Storage, Cloud Functions gen 2). It grew out of Festival Quest (Lancaster Music Festival, October 2026), which is now the `lancaster` **game pack**; each new game is a new pack. **README.md** explains the rules, packs, scoring rule sets, scripts and local setup; read it before changing game behaviour.

## Working with the user

- The user is the developer and usually the game master (GM) of whatever game is being built.
- Keep replies short: give the outcome first, then one clear yes/no question when you need something.
- The live game is the `mystery` pack on `musical-mischief` (the `prod` alias; functions env in `functions/.env.musical-mischief`, web config in the untracked `.env.production.local`, served by Firebase Hosting). Ask before anything that touches it: `npm run deploy` (a `--dry-run` is fine), `firebase deploy`, a `--prod` script, a write to its data, or running the Pages workflow. Pushing to GitHub needs asking too.
- The Lancaster game's own repository (`~/projects/LancasterLunaticsMusicalMischief`) is separate and finished; don't change it from here. It ran on the same Firebase project before the mystery game took it over.
- Show the user visual options before committing to a new look for a pack.

## Toolchain

- **Node 24 via nvm.** Prefix shell commands with `export PATH=~/.nvm/versions/node/v24.13.1/bin:$PATH`. The system Node is v20, which breaks firebase-tools and rules-unit-testing. The firebase CLI is a dev dependency: `npx firebase`.
- **Java 21** is installed; the emulators need it.
- **gcloud** (snap) is signed in as the user with Application Default Credentials. There is no `gh` CLI.
- Don't mint tokens from the firebase CLI's stored credentials; use gcloud or ADC instead.

## Commands

| Command | Use |
|---|---|
| `npm run typecheck` | App plus functions (src and test tsconfigs). Silent on success. |
| `npm test` | Builds functions, then runs every suite (unit, rules, functions on the emulator, functions-memory, engine guard) inside `firebase emulators:exec`. Needs ports 8080/9099/9199/4400/4500 free, so it fails while `npm run dev` runs (or run `npx firebase emulators:exec --config <alt config> … "npx vitest run"` with other ports). |

| `npm run mock` | The whole game in the browser on in-memory demo data (no Firebase, emulators or Java); `VITE_GAME_PACK` picks the pack. `npm run build:mock` builds it as a static demo. |
| `npm run dev` | Local stack: functions watcher, emulators, Vite on :5173, dev ticker, auto-seed. Pack from `VITE_GAME_PACK` / `functions/.env.local` / `GAME_PACK` (default `lancaster`). |
| `npm run seed -- --pack <id>` | Seeds game state, settings and the pack's catalogue. `--demo` adds demo players; `--switch-pack` re-points a game seeded for another pack. |

| `npm run deploy` | Deploys the live game (`prod`): checks Node, the env files, matching packs and the functions' secrets, runs typecheck and the unit tests, builds, asks once, then rules + functions before hosting. `--only web,functions,rules`, `--dry-run`, `--skip-tests`, `--yes`. ## Data layer (swappable backend)

- **Rules side:** game code takes a `Store` (`functions/src/shared/store/types.ts`), never Firestore. Times are `Stamp`s; `fail()` throws `GameError`; store failures are `StoreError`s. Implementations: `firestoreStore` (`functions/src/firebase/store.ts`) and `memoryStore` (`functions/src/shared/store/memory.ts`). Only `functions/src/firebase/**` and `functions/src/index.ts` may import `firebase-admin`/`firebase-functions`; nothing in `functions/src/game` or `shared` may import `node:*` (it runs in browsers too).
- **Registries:** every callable is in `functions/src/game/callables.ts` and every trigger in `triggers.ts`. `index.ts` maps them onto Cloud Functions with explicit `export const` lines; the mock runs them directly. A new action goes in the registry, `index.ts` and `src/api.ts` (a test checks all three agree).
- **App side:** everything goes through `backend()` (`src/backend/index.ts`): `auth`, `data.watchDoc`/`watchQuery` (plain `QuerySpec`s; `useQuery(spec)` in `src/data/hooks.ts`), writes with `SERVER_TIME`, `call`, `files`, `push`. Only `src/backend/firebase/` imports `firebase/*`. `VITE_BACKEND=mock` swaps in `src/backend/mock/`.
- **Parity:** the whole functions test suite runs on both stores (`functions` on the emulator, `functions-memory` in memory), and `functions/test/store/conformance.ts` runs against both stores. Keep both green; a new Firestore feature in the rules needs adding to `Store`, both stores and the conformance suite.
- **Demo data:** `functions/src/shared/demo/` builds it as plain data; `scripts/seed.mjs --demo` writes it to Firestore and the mock loads it. A `DemoFile` is SVG `text` or a `clip` from `demo/clips/` (the video entries of a pack's video story mission, opened with its vote; CC-licensed, see `CREDITS.md` there): the mock serves clips through `import.meta.glob`, the seed reads them from disk.
- **Node scripts** import shared TypeScript directly (type stripping): no parameter properties and `.ts` import extensions in `functions/src/shared/**`.

## Scoring

- Rule sets live in `functions/src/shared/scoring/` (`classic`, `countdown`, `heist`; registry `RULESETS`). Each is pure: `score(event, ctx)` → points lines or transfers; `describe()` → House rules rows.
- `engine.ts` resolves the rule set (`settings.scoring` → pack default → classic) and its params (`settings.scoringParams`), checks and rounds lines, and plans the zero floor and transfers.
- In game code every rule-set-scored change goes through `applyScore` in `functions/src/game/ledger.ts`; `applyPoints` is only for GM adjustments and fraud reversals (which always take back exactly `pointsAwarded`).

## Architecture

- **`functions/src/index.ts`** registers every callable and trigger (region europe-west2, `maxInstances` 10) and builds `Ctx`.
  - Game logic lives in `functions/src/game/*.ts` as `doX(db, ctx, data)` functions.
  - `Ctx` carries `uid`, `now`, `rng` and `pack`; `db` is a `Store`. Game code never reads `Date.now()`, `Math.random()` or `process.env`, so tests can pin time, randomness and the pack. Keep it that way.
  - Guards (`requireGM`, `loadSettings` and similar) are in `game/guards.ts`. Multi-document changes run in transactions, reads before writes.
  - Feature gates (guesses, side quests) are the first statement of their callables.
- **Shared code:** `functions/src/shared/` (types, settings, packs, scoring, ranking, rerolls, votes). The app imports it through `src/shared.ts` or directly; the scripts import it directly (Node 24 strips types), so value imports inside `functions/src/shared/**` use `.ts` extensions.
- **Firestore collections:** `game/{state,settings,final,switchboard,top}` (`final` also holds `closing`, the pack's closing hook's result; `state` also holds the GM's start time: `opensAt`, kept once the game opened itself and cleared by opening by hand, and `opensMoved {from, at}`, the last move; `switchboard`: the police phone breaker, GM-only read, functions write; `top` (`TopPost`): the log book's pinned entry in `reactions: 'votes'` packs, players and the GM read, only the reaction trigger writes it, a reset deletes it and ending the game keeps it), `admins/{uid}`, `joinRequests/{uid}`, `players/{uid}` with `quests/{qid}` (the owner writes only `displayName` (lobby only) and `photoURL`; `bookedAt` (null from approval, absent on docs from before onboarding) and `particulars` (`heightCm`, `relation` (an id from `pack.booking.relations`), `marks`, and an old doc's `drink`; `checkParticulars(raw, pack.booking)` in `functions/src/shared/booking.ts`) only through `bookIn`), `questTemplates/{id}` (seeded `p-…`/`g-…`), `globalQuests/{id}` (side quests; `voteStyle` (`'pick'` / `'yesno'`, copied from `settings.voteStyle` by `startVoting`), `question`, and at close `tally` (votes, or yes − no) and `yesNo`) with `votes/{uid}` (`{submissionId}` or `{ballot}`, written by `castVote` (`vote: 'yes' | 'no'` in a yes/no vote); only that voter may `get` their own, nobody lists them), `submissions/{id}` with `entryReactions/{uid}` (an eye and a heart on someone else's revealed side-quest entry, `{eye, heart, updatedAt}`, written by the player; the `onEntryReactionWritten` trigger keeps `entryReactions: {eye, heart}` uid lists on the entry), `guesses`, `pointsLedger`, `feed/{id}` with `reactions/{uid}` (`{emoji, createdAt}`, or in a votes pack `{vote: 1 | -1, createdAt}`; the `onFeedReactionWritten` trigger keeps the post's `reactionCount` and, for votes, `up`, `down`, `score` and `votes {uid: 1|-1}`, then recomputes `game/top`: best `score >= 1` among unflagged posts of a `TOP_FEED_TYPES` type (a player's own entries: `approved`, `checkin-answer`, `global-won`), ties to fewer downs, the holder, the earlier post; while the game is active or paused, the holder's player is paid `settings.topEntryPoints` (`topEntry` event, ledger `top-entry`). That is recorded as `game/top.award {uid, feedId, points}` and taken back exactly (`top-entry-lost`) when another player's entry takes the top or it empties; never paid to, or taken from, a player who left; `since` moves only on a change of holder, which also sets `previousFeedId` / `previousSince`; a fraud override recomputes it too), `wraps/{uid}`, `locations/{uid}`, `pushTokens`, `facts/{key}` (what the story settled, from an announcement's `fact` or a mission's `records`: players and the GM read; functions write; wiped on reset) and `assignments/{globalQuestId}_{uid}` (who a player was dealt for an `entry.tag: 'assigned'` mission; that player and the GM read; functions write; wiped on reset), `rewards/{submissionId}` (reward choice; owner and GM read only, so frames stay anonymous) `motives/{uid}` (characters; that player and the GM read only; the GM's `setCharacter`, or, when a dealt mission with `entry.writesMotive` closes, what another player wrote, with `byUid`) `periodics/{id}` (periodic missions: the GM's series, GM-only read) and `checkins/{id}` with `answers/{uid}` (what they send: everyone in the game reads; only functions write any of them, through `managePeriodic`, `answerCheckin` and the timer's `runPeriodics`) and `policeCalls/{id}` (police check-ins: that player and the GM read; only functions write, through `answerPoliceCall`, `tipOffPolice`, the `onPlayerWritten` trigger, the timer's `runPolice` and, by phone, `onPoliceCallCreated` and the `policeVoice` webhook; `channel` phone or app, `phone` (Twilio's sid, status, result), `fallbackReason`) and `lineOrders/{id}` (work waiting for the Telegram police script: `kind` call or test (`to`, `query`, `sid` `TG-…`) or notice (`to`, `text`: a case update), `status` new/taken/dropped; no client access; functions write; wiped on reset and at game end) and `game/line` (the script's heartbeat `{kind, seenAt, account, features}`, `features` `['notices']` while it takes case updates; GM-only read; wiped on reset) and `phones/{uid}` (a player's police line: E.164 number (also how the Telegram line finds them), status, test call; that player and the GM read; only functions write, through `setPoliceLine`, `testPoliceLine` and `policeVoice`; wiped on reset and at game end) and `stops/{id}` (the GM's route: `order`, optional times, `revealed`, and for a real bar its `address`, `placeRef` and `placeName`; players may read only revealed stops, so their query filters `revealed == true`; the GM reads all and writes from the app; a reset keeps them; revealing posts a `stop-revealed` feed item).
- **The timer:** every 5 minutes the schedule runs `runOpening` (opens a lobby game whose `opensAt` has passed; the app also calls `openOnTime` at zero, and both share one idempotent transaction in `game/startTime.ts`, which also has the GM's `setStartTime`), `runTick` (side quests), `runPeriodics`, `runStandings` (re-checks each player's standing after the GM moves the lines), `runPolice` (also re-sends phone calls Twilio went quiet on) and `runSwitchboard` (settles stale test calls; while the lines are down, a Twilio account check every 15 min) and `runVerdicts` (the log book's verdicts, votes packs); `devTick` and the mock run the same seven (with the simulated phone line). Player standings (`standing`, trusted confidant / person of interest) are kept by the `onPlayerWritten` trigger, which must stay idempotent because it fires on its own write. The `onSubmissionWritten` trigger pushes to a claim's new witness when `witnessUid` differs from `witnessNotifiedUid` (also set by `onSubmissionCreated`), so it never pushes twice.
- **Police calls over Telegram (`POLICE_LINE=telegram`):** the line is `telegramLine(db, now)` in `functions/src/game/telegramLine.ts` (a `PhoneLine` with `callerId` `''`: `placeCall` writes a `lineOrders` doc, or throws `line-offline` when `game/line` is older than `LINE_OFFLINE_MS`); `handleTelegramLine` takes the script's ops `heartbeat`, `poll` and `event` (becomes a `handlePoliceVoice` request; `renderTelegram` turns the reply into steps, already worded for the chat because `policePhone` asks `voiceScript` with `chat: true` on a `TG-` sid; `messageFor` lists the options; the reply carries the officer's `voice`; `claimOrders` hands out up to 5, oldest first, and drops a notice older than 10 min). The HTTPS side, `telegramLine` (`functions/src/firebase/telegram.ts`), checks an HMAC-SHA256 over `timestamp.body` with the secret `TELEGRAM_LINE_SECRET`. `policeLineConfig(process.env)` (`firebase/lineConfig.ts`) picks the line (Twilio, Telegram, simulated) and the only secrets `index.ts` declares. On a `TG-` sid, a picked-up call that gets a wrong or no reply is fined `heardPenalty` (from `policeHeardPenalty`, copied onto the call; `scoreAnswer` / `chargeMissed` take the override), not picked up is the full `failPenalty`, and `stalledPhoneCode` waits `TELEGRAM_GIVE_UP_MS` (5 min). The script is `services/telegram-police`.
- **Case updates (`settings.policeNotices`):** `Services.sendPush` is `deliverPush` (`functions/src/game/notices.ts`): while `noticesOpen` (the setting, a fresh `game/line` beat listing `notices`), a push to a player whose `phones/{uid}` is verified with a `TG-` test (`noticeNumber`) becomes a `notice` order (`noticeText`: "title: body") and the rest get the push; GM-only plans always push. The script prefixes `⚠️ Case update ⚠️ - `, deletes its earlier case updates in that chat, paces notices a second apart through one outbox apart from calls, and drops `notices` from its heartbeat for an hour after a flood error.
- **Police phone calls (Twilio):** see `design/twilio-setup.md`. Game code reaches Twilio only through the injected `PhoneLine` (`functions/src/game/phoneLine.ts`; `Services.phone()`: Twilio's; the simulated line in the mock and the emulators (`functions/src/game/simulatedLine.ts`: calls get `SIM-` ids from a drama-range number, and the app's `SimulatedPhone` plays the phone through the `simulateCall` callable, exported only in the emulators, which feeds `handlePoliceVoice` what Twilio would); null in deployments without `POLICE_CALLER_ID`, where `testPoliceLine` refuses with `details.reason: 'not-set-up'`); the real one, the `X-Twilio-Signature` check and the webhook's HTTP side are in `functions/src/firebase/twilio.ts`. `policeVoice` (HTTPS, only deployed with `POLICE_CALLER_ID` in `functions/.env.<project id>`) routes to `handlePoliceVoice`; callables and triggers that use the line (to ring, or for `setPoliceLine` just its caller ID) declare `phone: true` in their registry entry so `index.ts` binds the `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` secrets to them. The breaker and routing rules are pure, in `functions/src/shared/switchboard.ts`. Tests use a fake `PhoneLine`; nothing ever calls Twilio from a test.
- **Police calls on Telegram:** `services/telegram-police/` (Python 3.11: Telethon and py-tgcalls in its own `.venv`; keys in its gitignored `.env`, the login in `police.session`, and both in Secret Manager in `musical-mischief` as `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` and `TELEGRAM_POLICE_SESSION`, read with `POLICE_SECRETS_PROJECT` set; `store-secrets` refreshes them) logs in as the police's own Telegram account (the spare number; not a bot, since bots can't call) and rings a player's Telegram by username or number, playing a recording or an edge-tts line. `police_call.py serve` takes the game's calls and case updates (live on the `telegram-police-line-vm` VM in `musical-mischief`, us-central1-a, `~/police-line`, systemd unit `police-line`; copy the script there and restart after a change). ## Engine defaults the user decided (Festival Quest rules; keep unless asked)

- **Joining:** anyone can sign in and request to join; a GM must approve. No join codes.
- **Claims:** a claim names a **witness** (another player), who approves or rejects it. Nobody approves their own claim, the GM included. No auto-approval.
- **GM powers:** only the GM can reject an approved claim: a **fraud override** takes the points back, charges the `fraudPenalty` fine and swaps the quest.
- **Quests** never depend on a location or a win rule. Personal quests stay discreet and end with a `Proof:` line.

## Code conventions

- Match the surrounding code: comment density, naming, small pure helpers, CSS per screen area, colours only as tokens.
- Game logic changes come with tests in `functions/test/`; rules changes with tests in `tests/rules/`; pure helpers get `*.test.ts` next to them; new rule sets get cases in `functions/test/scoring.test.ts`.
- Update README.md when behaviour, scoring, packs or commands change.
- Never commit `.env.local` or credentials. `functions/.env` holds only the pack id.
